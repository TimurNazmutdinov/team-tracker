# team-tracker

Трекер задач и спринтов для команд разработки: проекты с ключами задач, бэклог, доски, спринты, story points, burndown и velocity.

**Статус: в разработке.** Готовы документы, макеты, приложение на демо-данных (этапы 0–7) и рабочая база: сервер Node.js + Fastify со входом и ролями, на встроенной базе без установки PostgreSQL или на PostgreSQL ([запуск на Windows](#запуск-на-своём-компьютере-windows)). Стек: React + TypeScript + Vite на клиенте ([ADR-002](docs/adr/002-stack.md), [ADR-010](docs/adr/010-server-auth-roles.md)).

## Демо и запуск

**Демо:** https://timurnazmutdinov.github.io/team-tracker/ (публикуется из ветки `main`; данные берутся из `data/seed.json`, изменения хранятся в вашем браузере).

Локальный запуск (нужен Node.js 22):

```bash
npm install
npm run dev
```

Приложение откроется на http://localhost:5173/. Кнопка «Меню → Сбросить данные» возвращает демо-данные к исходным.

Команды: `npm run lint`, `npm run typecheck`, `npm test`, `npm run build`, `npm run format:check`; проверка seed — `python3 scripts/check_seed.py`. Все они же выполняются в CI (GitHub Actions) для каждого pull request и push в `main`.

Состояние: готовы каркас (этап 3), задачи с бэклогом (этап 4), доска (этап 5), спринты (этап 6), отчёты (этап 7) и рабочая база с входом и ролями (этап 8). Публикация на внешнем сервере пока не настроена.

## Запуск на своём компьютере (Windows)

Трекер с общей базой, входом и ролями ([ADR-010](docs/adr/010-server-auth-roles.md), [ADR-011](docs/adr/011-local-pglite.md)) работает на одном компьютере **без Docker и без установки PostgreSQL**: данные хранятся во встроенной базе в папке `local-data`. Команды ниже выполняются в «Терминале» или «Командной строке»: откройте папку проекта в Проводнике, нажмите на адресную строку, введите `cmd` и Enter.

### Первый запуск

1. **Установите Node.js LTS** (версия 22 или новее): скачайте установщик с https://nodejs.org, нажимайте «Далее». После установки откройте новое окно командной строки и проверьте: `node -v`.
2. **Скачайте проект:**

   ```bat
   git clone https://github.com/TimurNazmutdinov/team-tracker.git
   cd team-tracker
   ```

   Git берётся с https://git-scm.com. Если Git ставить не хочется — на странице репозитория «Code → Download ZIP» и распакуйте архив.

3. **Установите зависимости:** `npm install` (один раз, пара минут).
4. **Создайте файл настроек:** `copy .env.example .env`. Значения по умолчанию подходят; описание каждой настройки — в самом файле.
5. **Создайте администратора:** `npm run admin:create` — программа спросит почту, имя и пароль (не короче 8 символов). Регистрации на экране входа нет: учётки создаёт администратор.
6. **Запустите трекер:** двойной щелчок по `start.cmd` в папке проекта (или `npm run start`). Откроется браузер; если нет — введите http://localhost:3000. Первый запуск собирает интерфейс и занимает около минуты.
7. **Войдите** почтой и паролем администратора. Участников добавляйте на экране «Люди» → «Новый участник»: интерфейс покажет временный пароль (один раз) — передайте его человеку, при первом входе он придумает свой. Забытый пароль — кнопка «Сбросить» рядом с участником.

Окно, которое открыл `start.cmd`, **не закрывайте**: пока оно открыто, трекер работает. Остановить — закрыть окно или Ctrl+C. Демо-данные (необязательно, только в пустую базу): `npm run db:seed`.

### Как обновить

Остановите трекер, затем в папке проекта:

```bat
git pull
npm install
```

и снова запустите `start.cmd` — интерфейс пересоберётся сам, а база обновится автоматически при запуске. Перед обновлением сделайте копию.

### Как сделать копию и восстановить

Остановите трекер (копия делается только при остановленном трекере), затем:

```bat
npm run backup
```

Копия появится в папке `backups\` с датой и временем в имени, например `tracker-20261028-183000.tar.gz`; хранятся 14 последних. Время от времени копируйте эту папку на другой диск или флешку. Восстановление (тоже при остановленном трекере):

```bat
npm run restore backups\tracker-20261028-183000.tar.gz
```

Прежние данные не удаляются, а переименовываются в `local-data.before-restore-…`; убедившись, что всё в порядке, эту папку можно удалить.

### Как открыть доступ коллегам по локальной сети

По умолчанию трекер виден только на этом компьютере (`HOST=127.0.0.1`). Чтобы коллеги заходили со своих компьютеров:

1. В файле `.env` замените строку на `HOST=0.0.0.0` и перезапустите трекер.
2. Разрешите входящие подключения к порту 3000 в брандмауэре Windows. Командная строка **от имени администратора**:

   ```bat
   netsh advfirewall firewall add rule name="team-tracker" dir=in action=allow protocol=TCP localport=3000 profile=private
   ```

   (то же через «Брандмауэр Защитника Windows → Дополнительные параметры → Правила для входящих подключений → Создать правило → Для порта → TCP 3000 → Разрешить подключение → только «Частный» профиль»).

3. Узнайте адрес компьютера командой `ipconfig` (строка «IPv4-адрес», например `192.168.1.25`). Коллеги открывают `http://192.168.1.25:3000` и входят своими учётками.

Соединение не шифруется (HTTP), поэтому используйте это только в доверенной сети; не пробрасывайте порт в интернет. Компьютер с трекером должен быть включён.

### Если что-то не работает

- **«Трекер уже запущен»** — открыто другое окно с трекером; закройте его. Если окон нет, а сообщение осталось, перезагрузите компьютер.
- **Порт 3000 занят** — измените `PORT` в `.env` и открывайте новый адрес.
- **Забыли пароль администратора** — другой администратор нажимает «Сбросить»; если администратор один, создайте второго: `npm run admin:create` с другой почтой.

## Docker и PostgreSQL

Режим с PostgreSQL остаётся для сервера и команд побольше. В файле `.env` задайте **обязательный** `POSTGRES_PASSWORD` (буквы и цифры), затем:

```bash
docker compose up -d --build
docker compose run --rm app npm run admin:create
```

Приложение откроется на http://localhost:3000 (порт — `APP_PORT`). Копии — `scripts/backup.sh` и `scripts/restore.sh backups/файл.sql.gz`. Свой PostgreSQL без Docker — переменная `DATABASE_URL` (см. `.env.example`).

Для разработки: `npm run server:dev` (сервер, порт 3000) и `VITE_STORAGE=api npm run dev` (интерфейс на порту 5173, запросы `/api` проксируются на сервер).

## Структура

- `src/app` — точка входа, маршруты, подключение хранилища
- `src/domain` — типы, схемы Zod, правила (чистый TypeScript)
- `src/storage` — интерфейс `TrackerStorage` и адаптеры `seed-local` (демо) и `api` (сервер)
- `server` — API на Fastify: вход, права, запись, копии, миграции Drizzle; `start.cmd`, `Dockerfile`, `docker-compose.yml`, `.env.example`
- `src/modules` — экраны по областям, `src/ui` — общие компоненты и стили, `src/state` — запросы и состояние интерфейса
- `data/seed.json` — демо-данные, `scripts/` — проверка seed, сборка схем и PDF
