# ADR-001. Доступ к данным через модуль хранения

- **Статус:** принято
- **Дата:** 2026-10-28

## Контекст

Сейчас данные берутся из `data/seed.json` и сохраняются в браузере. Позже появятся API и PostgreSQL на своём сервере или в облаке. Если экраны и логика будут обращаться к данным напрямую, переход на API потребует переписывать приложение.

## Решение

Весь доступ к данным идёт только через модуль хранения с типизированным интерфейсом. Экраны и логика (статусы, спринты, подсчёт points) не знают, откуда данные. Реализации интерфейса взаимозаменяемы: «seed + браузер» сейчас, «API + PostgreSQL» потом.

## Рассмотренные варианты

- **Прямые обращения к localStorage/fetch из экранов** — быстро на старте, но замена источника затрагивает весь код.
- **Модуль хранения с интерфейсом** — чуть больше кода на старте, зато источник меняется в одном месте, а логика тестируется на заглушке.

## Последствия

- Интерфейс хранения нужно описать и держать стабильным; он становится контрактом будущего API.
- Логика тестируется с in-memory реализацией.
- Запрещено импортировать реализацию хранения мимо модуля (проверять линтером).
