# ADR-020. Первое знакомство: мастер первого запуска и встроенная справка

- **Статус:** принято (часть 7 доработок; макеты — [wireframes.md](../wireframes.md), раздел 23)
- **Дата:** 2026-10-30

## Контекст

Свежая установка пуста для нового администратора: непонятно, с чего начать — проект, владелец, люди. Правила продукта (статусы, оценки, спринты, перенос, WIP, Definition of Done) и клавиши разбросаны по документам, а не по интерфейсу.

## Решение

**1. Мастер первого запуска.** Окно из четырёх шагов — «Проект», «Владелец», «Люди», «Гамма»; любой шаг можно пропустить, по шагам можно ходить в обе стороны. Шаги используют готовые действия: создание проекта, назначение владельца ([ADR-016](016-projects-portfolio.md)), создание учётки с временным паролем ([ADR-010](010-server-auth-roles.md); пароль показывается один раз), выбор гаммы ([ADR-013](013-logo-and-palettes.md)). Мастер показывается **только администратору при работе с сервером** (в демо-режиме без входа его нет) и только пока не пройден. Признак «пройден» хранится на сервере в таблице настроек (`settings`, ключ `onboarding`): `GET /api/onboarding` читает любой вошедший, `PUT /api/onboarding` меняет только администратор (право `users.manage`). Завершение, «Пропустить мастер» и закрытие по `Esc` запоминаются; администратор может запустить мастер заново из справки. Новых таблиц и миграций нет; seed и копии не меняются (настройка — служебная, как папка копий).

**2. Справка по «?».** Окно с тремя вкладками, открывается клавишей `?` (вне полей ввода) и кнопкой «?» в шапке: «Клавиши», «Правила» (статусы, story points, спринты, перенос, ёмкость и отпуска, WIP, Definition of Done, портфель и проекты, Markdown — коротко простым языком) и «Кто что может» — таблица прав по ролям, **построенная из той же проверки `can`**, что используют сервер и интерфейс, поэтому она не расходится с поведением (тип `Record<Action, …>` не даёт добавить право без подписи). Перечень клавиш «G + буква» берётся из той же таблицы, что обработчик клавиш, и проверяется тестом.

## Рассмотренные варианты

- **Подсказки-туры поверх интерфейса.** Хрупки при изменении экранов и мешают; выбрана справка по запросу.
- **Хранить признак мастера в профиле пользователя.** Мастер относится к установке, а не к человеку: второй администратор не должен проходить его снова; поэтому признак общий.
- **Показывать мастер в демо-режиме.** Там нет входа и ролей, а данные уже заполнены; пользы нет.
- **Внешняя документация вместо справки.** Не видна в момент вопроса и расходится с версией.

## Последствия

- Логика справки покрыта тестами `content.test.ts` (права из `can`, клавиши), эндпоинты — `server/src/onboarding.test.ts`; сквозные и доступность — прохождение мастера в `e2e/tests/01-flow.spec.ts`, справка и повторный запуск — `e2e/tests/07-onboarding.spec.ts`.
- Из набора клавиш, описанного на этапе макетов, не реализована смена статуса клавишами `S` + `1`–`5`: в интерфейсе нет понятия «выделенная задача»; в справку входят только работающие клавиши.
