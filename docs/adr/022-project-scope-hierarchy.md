# ADR-022. Единый выбор проектов в шапке; иерархия артефактов везде

- **Статус:** принято; макеты — [wireframes.md](../wireframes.md), раздел 25
- **Дата:** 2026-10-30

## Контекст

В шапке было два похожих элемента: чип проекта (куда ведут вкладки) и кнопка «Проекты: …» (какие проекты показывать). На доске при «Все» чип показывал один проект, и логика путала. Вложенность эпик → задача → подзадача была только на одном экране планирования, а в остальных списках задачи шли плоским перечнем.

## Решение

**1. Один выбор проектов** ([ADR-016](016-projects-portfolio.md)). Кнопка выбора проектов стоит на **всех** экранах слева в строке фильтров экрана (на экранах без своей строки фильтров — отдельной строкой под заголовком) и заменяет чип проекта (чип и переключатель из [ADR-021](021-roles-ui-polish.md) убраны). Название кнопки — сам выбор: у одного проекта «KEY · Название», иначе «Проекты: …»; отдельной метки в заголовке нет. На верхней панели фильтра нет. Вкладки шапки открываются для первого выбранного проекта, иначе для последнего открытого. Согласование: открытие экрана проекта включает его в выбор, если его там не было; смена выбора, исключающая проект открытого экрана одного проекта, переводит в первый выбранный проект (карточка задачи — в его планирование). Переход с карточки на экране «Проекты» на доску и планирование с фильтром этого проекта сохранён.

**2. Иерархия везде** (`domain/tree.ts`: `treeRows`, `ancestors`, `descendants`). Правило одно: Epic → Story, Task, Bug → Sub-task; потомок идёт сразу под родителем (линия и отступ), порядок соседей — как в списке; родитель, которого нет в списке, добавляется строкой-контекстом («вне спринта», «родитель»). Применено: состав спринта, прошлые спринты, «Люди» (задачи человека), планирование (эпик с задачами, свёртывание), портфель (эпик раскрывается до задач), дорожная карта (эпик раскрывается до задач по их спринтам), поиск Ctrl+K (путь до родителей под названием), карточка задачи (хлебные крошки «эпик › задача › …» и дерево подзадач), доска (путь до родителей на карточке).

## Рассмотренные варианты

- **Оставить чип и фильтр как есть, объяснив различие.** Различие реальное, но интерфейс не должен требовать объяснений.
- **Фильтр только на экранах, где он считает несколько проектов.** Выбор терялся бы при переходе на экран одного проекта; единый выбор проще.
- **Иерархия только по вложенности из списка.** Теряется контекст, когда эпик не в спринте; поэтому добавляются строки-контекст.
