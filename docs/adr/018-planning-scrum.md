# ADR-018. Планирование и Scrum-ритуалы: доступность людей, Definition of Done, ретроспектива, отчёт спринта

- **Статус:** принято (часть 5 доработок; макеты — [wireframes.md](../wireframes.md), раздел 21)
- **Дата:** 2026-10-30

## Контекст

Индикатор заполнения ([ADR-014](014-board-retro.md)) сравнивает points с velocity прошлых спринтов, не зная об отпусках. Нет общего критерия готовности, места для выводов команды и готового итогового отчёта спринта.

## Решение

**1. Доступность людей и ёмкость.** Новая сущность `Absence` (`personId`, `start`, `end`, `kind: vacation | sick | other`), общая для всех проектов (человек один). Рабочие дни — понедельник–пятница без праздников. Команда спринта — владелец и участники проекта ([ADR-016](016-projects-portfolio.md)); доступность = доступные человеко-дни ÷ все человеко-дни спринта (пересекающиеся отсутствия человека не считаются дважды). **Ёмкость = velocity по ADR-014 × доступность**, округление до десятых. Индикатор из ADR-014 не дублируется: меняется только значение ёмкости и поясняющая строка («velocity 16 sp × доступность 82 % (41 из 50 человеко-дней)», список отсутствующих). Без отсутствий доступность 100 % и вид индикатора прежний. Отсутствия добавляют, правят и удаляют тимлид и администратор (`people.availability`); экран «Люди» получает блок «Отсутствия».

**2. Definition of Done.** `Project.dod` — чек-лист Markdown («- [ ] …», ≤ 5000 символов), по умолчанию пусто (подтверждения нет). Меняют тимлид и администратор (как настройки спринтов). При переводе задачи в Done (доска и перетаскивание, строка статуса на карточке, массовое изменение статуса в доске и планировании) открывается окно с пунктами; «Подтвердить» доступна, когда отмечены все. Отметки не сохраняются: подтверждение каждый раз новое. Отмена оставляет статус прежним. Правило — чистая функция `dodRequired`.

**3. Ретроспектива.** Сущность `RetroItem` (`projectId`, `sprintId`, `kind: good | improve | action`, `text`, `authorId`, `createdAt`, `issueId`). Три списка в спринте, на экране «Спринты»; во вкладке «Прошлые спринты» — те же списки только для чтения. Добавляет любой, удаляет автор, тимлид и администратор (проверяется и сервером). Действие кнопкой «→ в задачу» создаёт задачу Task в бэклоге (метка «ретро», обычная запись истории `created`) и ставит записи `issueId`; повторно из того же действия задача не создаётся. Закрытый спринт тоже можно дополнять.

**4. Отчёт спринта.** Экран `/projects/:key/sprints/:id/report`: цель, выполнено и перенесено (sp и задачи), velocity, ёмкость с доступностью, burndown, итоги по людям, список задач, ретроспектива. Ничего не хранится — считается из задач, истории и записей ретроспективы (`domain/sprintReport.ts`). **Excel** формируется в браузере библиотекой `write-excel-file` (уже используется для копий, грузится только по кнопке): листы «Сводка», «Задачи», «Люди», «Burndown», «Ретроспектива». **Печать и PDF** — через печать браузера: стили `@media print` скрывают меню и кнопки.

**5. Данные и копии.** Миграция `0006_planning-scrum` (таблицы `absences`, `retro_items`, колонка `projects.dod`), Zod-схемы со значениями по умолчанию для старых данных, seed версии 5 (два отсутствия, четыре записи ретроспективы), `check_seed.py`. Резервные копии: JSON (`absences`, `retroItems`), Excel (листы «Отсутствия», «Ретроспективы», колонка «Definition of Done» у проектов); копии до этой версии восстанавливаются без них. Записи ретроспективы привязаны к проекту (границы проверки записи на сервере, [ADR-015](015-reliability.md)); отсутствия, как люди, общие.

## Рассмотренные варианты

- **Доступность по часам и рабочим календарям.** Избыточно для команды; выбраны рабочие дни пн–пт.
- **Праздничный календарь.** Зависит от страны и года; руководитель добавляет «Другое» на нужные даты.
- **Сохранять отметки Definition of Done у задачи.** Раздувает данные и историю; подтверждение разовое, а критерии приёмки задачи уже имеют чек-лист ([ADR-017](017-speed.md)).
- **Отдельный сервер для PDF.** Тяжёлая зависимость; печать браузера даёт PDF без неё.
- **Ретроспектива как задачи с меткой.** Смешивает выводы команды с рабочим бэклогом; отдельная сущность с явной ссылкой на созданную задачу.

## Последствия

- Логика покрыта тестами `availability`, `dod`, `retro`, `sprintReport`, `reportXlsx`, права — матрицей `permissions.test.ts`, копии — круговыми тестами; сквозные и доступность — `e2e/tests/05-planning.spec.ts` и `03-a11y.spec.ts`.
- Ёмкость в «Планировании» теперь зависит от отсутствий: при смене отсутствий индикаторы пересчитываются сразу.
