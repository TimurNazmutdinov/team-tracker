# ADR-011. Локальное развёртывание на PGlite

- **Статус:** принято
- **Дата:** 2026-10-28

## Контекст

Нужно, чтобы трекер работал на одном компьютере с Windows без Docker и без установки PostgreSQL: человек ставит Node.js, скачивает проект и запускает его двойным щелчком. Режим с PostgreSQL и Docker ([ADR-010](010-server-auth-roles.md)) остаётся. Для маленькой команды в одной сети такой запуск должен быть безопасным по умолчанию.

## Решение

1. **База.** Если `DATABASE_URL` не задан, сервер использует встроенную PostgreSQL-совместимую базу PGlite в папке `DATA_DIR` (по умолчанию `./local-data`, в `.gitignore`). Схема и запросы те же, что с PostgreSQL; миграции применяются при каждом запуске. Если `DATABASE_URL` задан — PostgreSQL, как раньше. Прежняя переменная `PGLITE_DIR` заменена на `DATA_DIR`.
2. **Одним процессом.** PGlite нельзя открывать двумя процессами сразу: данные повредятся. Рядом с папкой данных лежит метка `local-data.lock` с номером процесса сервера. Второй запуск, копия и восстановление видят живой процесс и отказываются; метка устаревшего (завершённого) процесса игнорируется и снимается при корректной остановке.
3. **Запуск.** `npm run start` (`scripts/start.mjs`) собирает интерфейс в режиме сервера, если сборки нет или исходники новее неё, ставит зависимости (`npm ci`), если `package-lock.json` новее установленных (после `git pull`), и запускает сервер: интерфейс и API на одном адресе. `start.cmd` в корне — то же двойным щелчком: проверяет Node.js, ставит зависимости, создаёт `.env` из примера и открывает браузер. Если трекер уже запущен, повторный запуск только открывает браузер и ничего не меняет под работающим сервером. Обновление — `git pull` и `start.cmd`; зависимости ставятся командой `npm ci`, а не `npm install`, чтобы не менять `package-lock.json` и не ломать следующий `git pull`.
4. **Только этот компьютер по умолчанию.** `HOST=127.0.0.1`; `HOST=0.0.0.0` открывает доступ по локальной сети (нужно правило брандмауэра Windows, описано в README). В Docker `HOST=0.0.0.0` задаётся в образе и в Compose.
5. **Регистрация закрыта** (`ALLOW_REGISTRATION=false`). Первого администратора создаёт `npm run admin:create` (почта, имя, пароль; флаги `--email --name --password` или вопросы в консоли). Новых участников создаёт администратор на экране «Люди» с **временным паролем**: его генерирует интерфейс и показывает один раз, на сервере хранится только хэш. До смены временного пароля сервер отдаёт только `/api/auth/me`, `/api/auth/password` и выход; смена закрывает остальные сессии пользователя. Администратор может выдать новый временный пароль (сброс) — так решается «забыл пароль». Открытая регистрация (`true`) по-прежнему даёт первой учётке роль администратора, остальным — разработчика. Экран входа берёт признак из публичного `GET /api/config` и без регистрации показывает подсказку «учётки создаёт администратор»; пока нет ни одной учётки, подсказывает `npm run admin:create`.
6. **Резервные копии.** *Заменено [ADR-012](012-backups.md): теперь комплект из Excel, JSON и копии базы, автоматически, без остановки трекера.* Исходное решение: `npm run backup` — архив папки данных PGlite (`dumpDataDir`) в `backups/tracker-ГГГГММДД-ЧЧММСС.tar.gz`, хранятся `BACKUP_KEEP` последних (14). `npm run restore <файл>` — восстановление в новую папку данных; прежняя переименовывается в `local-data.before-restore-<время>`, при ошибке возвращается на место. Обе команды работают при остановленном трекере. С PostgreSQL они отказывают и отсылают к `pg_dump` и `scripts/backup.sh`.
7. **Настройки.** Все переменные описаны в `.env.example`, `.env` в репозиторий не попадает и подхватывается сервером и командами сам; значения из окружения важнее. `POSTGRES_PASSWORD` в Docker Compose обязателен (`${POSTGRES_PASSWORD:?…}`).

## Рассмотренные варианты

- **SQLite.** Простая, но другая SQL-схема и драйвер: пришлось бы вести две схемы и миграции. PGlite — тот же PostgreSQL, один набор кода и тестов.
- **Установщик PostgreSQL для Windows.** Требует прав и ручной настройки; сложно для новичка.
- **Горячая копия при работающем сервере.** PGlite не допускает второго процесса; потребовался бы внутренний вызов сервера с проверкой прав. Для небольшой команды достаточно остановить трекер на минуту; автоматическая копия по расписанию — позже.
- **Оставить регистрацию открытой.** В локальной сети любой, кто видит адрес, мог бы создать учётку; закрытая по умолчанию безопаснее.

## Последствия

- Одна машина — один процесс сервера; PGlite рассчитана на небольшие данные, для нескольких десятков человек и дольше нужен PostgreSQL (перенос — через загрузку набора данных, отдельная задача).
- Копии лежат на том же компьютере: для надёжности их нужно периодически копировать на другой носитель.
- Временный пароль виден администратору; передавать его нужно безопасным каналом.
- Остановка по Ctrl+C снимает метку; при аварийном выключении метка останется, но её процесса уже нет — следующий запуск продолжит работу.
