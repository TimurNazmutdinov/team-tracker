# ADR-017. Скорость работы: палитра Ctrl+K, массовые действия, Markdown, шаблоны, WIP-лимиты

- **Статус:** принято (часть 4 доработок; макеты — [wireframes.md](../wireframes.md), раздел 20)
- **Дата:** 2026-10-30

## Контекст

Ежедневная работа требует много переходов и повторных действий: найти задачу, изменить статус или исполнителя у десятка карточек, оформить баг по одному порядку, показать структуру в описании. Лимиты незавершённой работы (WIP) в [ADR-014](014-board-retro.md) отложены; теперь их можно включать по желанию команды.

## Решение

**1. Командная палитра.** `Ctrl+K` / `⌘K`, `/` (когда фокус не в поле ввода) и кнопка «Поиск» открывают окно с полем ввода. Задачи ищутся по ключу и тексту среди проектов выбранного набора ([ADR-016](016-projects-portfolio.md)); порядок: точный ключ, номер, начало ключа, начало слова в названии, вхождение, описание; первые 8. Экраны и действия фильтруются по тексту. Клавиши вне полей: `C` — создать задачу, `G` и буква — переход на экран проекта. Чистая логика — `domain/search.ts`; окно — `combobox` и `listbox` с активным пунктом.

**2. Массовые действия.** `domain/bulk.ts`: статус, исполнитель, приоритет, добавление метки, спринт. Каждая задача меняется обычными правилами (`updateIssue`, `moveIssue`) и получает свои записи истории; результат «всё или ничего» — если хоть одну задачу изменить нельзя, не меняется ни одна, и сообщение называет причину. Сохранение — одним `commit`. Панель есть на доске одного проекта и в планировании; поля, недоступные роли, скрыты (статус — если можно менять все выбранные, приоритет — `backlog.rank`, спринт — `sprint.items`). Сервер проверяет права теми же `violations`.

**3. Markdown.** Описание, критерии и комментарии пишутся в Markdown (markdown-it, лёгкая и поддерживаемая библиотека). Показ безопасный: HTML в тексте отключён, разбор переводится в элементы React по белому списку (абзацы, заголовки, списки, цитаты, код, таблицы, ссылки), без `dangerouslySetInnerHTML`; ссылки только `http`, `https`, `mailto` с `rel="noopener noreferrer"`; картинки заменяются подписью; заголовки опускаются на два уровня. Поля имеют вкладки «Правка» и «Предпросмотр». Хранится исходный текст, формат данных не меняется.

**4. Чек-листы.** Строки `- [ ]` и `- [x]` показываются флажками с итогом «выполнено n из m» в заголовке критериев; отметка сохраняется сразу через `toggleChecklistItem` (`domain/checklist.ts`) обычным изменением поля «Критерии», то есть пишется в историю; пункты в блоках кода не считаются.

**5. Шаблоны задач.** Новая сущность `IssueTemplate` (`projectId`, `name`, `type`, `description`, `acceptance`); у каждого проекта по умолчанию «Баг», «Story», «Задача». Выбор — в окне создания (подставляет тип и тексты; при изменённом тексте спрашивает подтверждение). Правят тимлид и администратор (`project.templates`). Миграция `0005_templates-wip` (таблица `issue_templates`, добавляет шаблоны существующим проектам), Zod-схема со значением по умолчанию, seed версии 4, `check_seed.py`, лист «Шаблоны задач» в Excel и `templates` в JSON-копии; старые копии восстанавливаются без них. История задач не затрагивается (шаблон — настройка проекта, как участники).

**6. WIP-лимиты.** Поля проекта `wipEnabled` (по умолчанию `false`) и `wipLimits` (лимит на колонку To Do, In Progress, Review, Done; пусто — без лимита) в настройках проекта; меняют тимлид и администратор (как настройки спринтов). При превышении колонка помечена «⚠ WIP n из m», при переносе и массовой смене статуса показывается сообщение; **перенос не запрещается**. Считаются все задачи колонки в спринте без учёта фильтров доски. Правила — `domain/wip.ts`. Это **заменяет** решение «WIP-лимитов нет» из ADR-014: теперь это настройка, по умолчанию выключенная.

## Рассмотренные варианты

- **Запрет переноса при превышении.** Мешает аварийной работе; выбрано предупреждение.
- **Редактор WYSIWYG.** Тяжёлая зависимость и сложный формат хранения; выбран простой Markdown с предпросмотром.
- **Санитайзер готового HTML** (markdown-it с `html: true` + DOMPurify). Лишняя поверхность атаки; разбор в элементы React вставляет в страницу только известные теги.
- **Массовые изменения по одной задаче с отдельными сохранениями.** Частичный результат при ошибке; выбрано одно сохранение «всё или ничего».
- **Шаблоны на уровне всей системы.** Команды работают по-разному; шаблоны у проекта.

## Последствия

- Новые данные (шаблоны, WIP) идут через все слои: схемы, миграция, хранилища, сервер, копии JSON и Excel, права. Логика покрыта тестами `search`, `bulk`, `checklist`, `templates`, `wip`, `Markdown` (включая попытки XSS) и круговым тестом копий.
- Зависимость `markdown-it` (≈ 100 КБ в сборке) загружается вместе с интерфейсом.
- Массовые действия на доске нескольких проектов не предлагаются: выберите один проект ([wireframes.md](../wireframes.md), раздел 15).
