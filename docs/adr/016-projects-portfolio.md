# ADR-016. Владелец и участники проектов, фильтр по проектам, «Портфель»

- **Статус:** принято (часть 3 доработок)
- **Дата:** 2026-10-29

## Контекст

Продакт ведёт несколько проектов. Нужно видеть, в каких он участвует, смотреть задачи сразу нескольких проектов, не терять время на переходы и замечать проблемные проекты (перегруз, просрочки, блокировки). Раньше проект не знал о людях: роль продакта действовала на все проекты разом.

## Решение

**1. Данные.** `Project.ownerId` — продакт-владелец (может быть не задан у созданных ранее проектов). Новая сущность `ProjectMember` (`projectId`, `personId`, `role: product | lead | developer`); владелец среди участников не повторяется, участник в проекте уникален. Миграция БД `0004_project-members` (таблица `project_members`, `projects.owner_id`, `users.project_filter`), Zod-схемы со значениями по умолчанию для старых данных, seed версии 3 (владелец `u1`, три участника), проверка `check_seed.py`. Резервные копии включают владельца и участников в `tracker.json` и в Excel (лист «Участники проектов», колонка владельца); копии до этой версии восстанавливаются без них. Записи `History` ведутся по задачам, поэтому смена владельца и участников в неё не пишется (журнала проекта нет).

**2. Права** (`domain/permissions.ts`, одна проверка для сервера и интерфейса). Владельца меняет администратор; участников — администратор и владелец проекта. **Продакт** меняет порядок, приоритеты и состав спринтов, а также создаёт задачи сразу в спринте только в проектах, где он владелец или участник; тимлид и администратор не ограничены проектом, разработчик — как раньше. Видимость проектов не ограничена: «Мои проекты» — удобный набор, а не запрет; администратор выбирает «Все» наравне с другими.

**3. Фильтр по проектам** (`domain/projectScope.ts`): выбор «Мои», «Все» или перечень ключей. Порядок источников: параметр адреса `?projects=…` (`mine`, `all` или ключи через запятую) → сохранённый выбор пользователя (с сервером `users.project_filter` через `PATCH /api/auth/preferences`, в демо `localStorage`) → проект из адреса `/projects/:key/…` → «Мои». Выбор применяется сразу, пишется в адрес и в профиль. Фильтр есть на доске, в планировании, «Прошлых спринтах», отчётах и «Портфеле»; поиск и Ctrl+K (часть 4) возьмут тот же выбор.

**4. Несколько проектов на экранах.** Доска: общие колонки статусов, дорожка на проект с его активным спринтом, метка проекта на карточке, перенос только по колонкам своего проекта, группировка по проектам. Планирование: отдельный блок на проект (перенос между проектами невозможен). «Прошлые спринты»: общий список от новых к старым с меткой проекта. Отчёты: velocity по каждому проекту; burndown и итоги по людям — для одного проекта.

**5. «Портфель»** (`/portfolio`, `domain/portfolio.ts`): по проекту — активный спринт, дни до конца, выполнено sp и %, мини-burndown, задачи по статусам, заполнение против ёмкости ([ADR-014](014-board-retro.md)), просроченные (не Done со сроком в прошлом) и заблокированные (блокирует не завершённая задача) задачи, прогресс эпиков. Признаки риска: перегруз, закончившийся, но не закрытый спринт, просрочки, блокировки; сортировка по риску (сумма весов 3, 3, 2, 2) или проекту, фильтр «Только с риском».

**6. Скорость.** Сервер проверяет запись в границах затронутых проектов ([ADR-015](015-reliability.md)): набор для проверки теперь включает участников этих проектов.

## Рассмотренные варианты

- **Ограничить видимость проектов участием.** Сломало бы текущие учётки без участия; «Мои проекты» остаются набором для фильтра.
- **Хранить выбор только в адресе.** Теряется между сессиями; нужен сохранённый.
- **Роль в проекте вместо роли доступа.** Слишком большая переделка прав; роль в проекте пока информативная, а ограничение даётся только продакту.
- **Объединить планирование проектов в один список.** Спринты и порядок задач у каждого проекта свои; смешивание привело бы к переносам между проектами.

## Последствия

- Новые данные в `Dataset`, `Changes`, хранилищах (`getMembers`), API (`GET /api/members`), резервных копиях.
- Существующие проекты после обновления без владельца и участников: продакты не смогут менять порядок в них, пока администратор не назначит им владельца или участников (ограничение действует только на роль «продакт»).
- Поиск и Ctrl+K подхватят выбор через `useProjectScope()`.
