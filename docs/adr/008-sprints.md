# ADR-008. Спринты и настройки проекта

- **Статус:** принято
- **Дата:** 2026-10-28

## Контекст

Этап 6 реализует спринты: создание и правку, запуск, закрытие с переносом незавершённого (F-08, F-09), итоги по людям и спринтам (F-13) и настройки спринтов проекта (F-28). Общие правила уже записаны в [ADR-003](003-business-rules.md); здесь — детали реализации и новые решения.

## Решение

1. **Жизненный цикл.** `planned` → `active` → `closed`. Запустить можно только запланированный спринт и только если нет другого активного; закрыть — только идущий. Создание и правка (название, цель, даты) — для запланированного и идущего; закрытый только для чтения. Название спринта уникально в проекте; дата окончания строго позже даты старта.
2. **Закрытие.** В `closedAt` пишется момент закрытия. Незавершённые задачи верхнего уровня (не Sub-task, статус не Done) переносятся вместе со всеми своими подзадачами: в существующий спринт `planned`, в бэклог или в новый спринт, который создаётся в том же действии. События `sprintId` пишутся с тем же моментом `closedAt`, поэтому закрытый спринт не меняется после закрытия. Если все задачи в Done, цель переноса не нужна.
3. **Подзадачи при закрытии.** Подзадача всегда в спринте родителя (ADR-003, п. 9), поэтому решает родитель: выполненная подзадача незавершённого родителя переносится с ним; **незавершённая подзадача выполненного родителя остаётся в закрытом спринте** — окно закрытия предупреждает об этом.
4. **Velocity** — сумма story points задач в Done в момент закрытия. В окне закрытия она показывается заранее; графики появятся на этапе 7.
5. **Итоги не хранятся.** Итоги по людям (задач, sp, из них в Done) и по статусам считаются из задач; для закрытого спринта — из состава и значений на момент закрытия, восстановленных по истории (откат событий `sprintId`, `status`, `assigneeId`, `points`). Поэтому последующие правки перенесённых задач не меняют итоги закрытого спринта. Для этого хранилище отдаёт историю всего проекта (`getProjectHistory`).
6. **Настройки спринтов проекта (F-28).** В проект добавлены поля: `sprintDurationDays` (1–90), `sprintPrefix`, `nextSprintNumber`, `nextSprintStart` (дата или `null`). Форма нового спринта подставляет название «префикс номер» (занятые названия пропускаются), дату старта (заданную в настройках, иначе следующий день после конца последнего спринта, но не раньше сегодняшнего дня) и конец = старт + длительность − 1 день. Конец следует за началом, пока его не правили вручную. Когда создаётся спринт с предложенным названием, `nextSprintNumber` растёт на 1; использованная `nextSprintStart` сбрасывается. Все значения в форме можно изменить.
7. **Данные.** В `seed.json` появился запланированный «Спринт 3», у проекта — настройки (14 дней, «Спринт», следующий номер 4); версия seed — 2.

## Рассмотренные варианты

- **Переносить подзадачи независимо от родителя** — нарушает правило «подзадача в спринте родителя».
- **Запрещать закрытие спринта с незавершёнными подзадачами выполненных родителей** — мешает работать; предупреждения достаточно.
- **Хранить итоги закрытого спринта в самом спринте** — дублирует данные; восстановление по истории уже нужно для отчётов.
- **Длительность в неделях** — не покрывает короткие и нестандартные спринты; дни точнее.

## Последствия

- Проект стал богаче: схема, seed и документы обновлены; версия seed 2 сбрасывает устаревшие данные в браузере.
- Отчёты этапа 7 используют те же функции восстановления состояния по истории.
- Вход и роли теперь ADR-009 (предстоит).
