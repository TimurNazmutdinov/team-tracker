# ADR-004. Решения по макетам экранов

- **Статус:** принято
- **Дата:** 2026-10-28

## Контекст

В [wireframes.md](../wireframes.md) остались вопросы по экранам. Их нужно закрыть до реализации каркаса (этап 3) и экранов (этапы 4–6).

## Решение

1. **Колонка Backlog на доске не показывается.** На доске только задачи выбранного спринта; задачи вне спринта живут в бэклоге.
   Причина: доска отвечает на вопрос «что в работе в спринте».
2. **Sub-task — отдельные карточки с меткой родителя** («↑ DEMO-9»). Среди группировок доски есть «по родителю».
   Причина: подзадачи имеют свой статус и исполнителя; без отдельной карточки их нельзя двигать по колонкам.
3. **Горячие клавиши** — набор из раздела 12 wireframes.md (`C`, `/`, `?`, `G` + `B`/`D`/`S`/`R`, `Ctrl+Enter`, `Esc`) и смена статуса выделенной задачи: `S`, затем `1`–`5` (Backlog, To Do, In Progress, Review, Done).
   Причина: смена статуса — самое частое действие, оно должно быть доступно без мыши.
4. **Тема — по настройке системы** (`prefers-color-scheme`). Ручной переключатель — позже.
   Причина: не нужно хранить выбор и рисовать переключатель; поведение ожидаемо.
5. **Новый спринт создаётся из окна закрытия**, отдельного шага нет.
   Причина: тот же поток, что в [ADR-003](003-business-rules.md), п. 8.
6. **Экран «Проекты» есть.** Адреса `/` и `/projects`; если проект один, `/` сразу открывает его бэклог. Список проектов доступен по `/projects` и из переключателя проекта.
   Причина: при одном проекте лишний экран только мешает, но он нужен для создания проектов и будущих серверных данных.
