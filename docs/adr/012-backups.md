# ADR-012. Резервные копии: комплект из Excel, JSON и копии базы

- **Статус:** принято
- **Дата:** 2026-10-29

## Контекст

Данные команды живут в одной базе на одном компьютере ([ADR-011](011-local-pglite.md)). Нужны копии, которые (а) делаются сами и без остановки трекера, (б) проверяются, (в) читаются человеком без трекера (Excel) и (г) надёжно восстанавливаются. Копии должны уходить в выбираемую папку, в том числе в облачную (Dropbox, OneDrive, Яндекс.Диск). Прежние `npm run backup` и `restore` из ADR-011 (архив папки данных, только при остановленном трекере) заменяются этим решением.

## Решение

**1. Снимок без остановки.** Данные читаются в одной транзакции `REPEATABLE READ`, только для чтения: параллельные записи трекера не блокируются и не попадают в снимок наполовину. Снимок = все таблицы данных и учётные записи (с хэшами паролей).

**2. Комплект** в `BACKUP_DIR/ГГГГ-ММ-ДД_ЧЧ-ММ/` (местное время):
- `tracker.json` — полный снимок, **основной путь восстановления**;
- `tracker.xlsx` — то же для чтения человеком и запасной путь восстановления;
- копия базы «как есть»: `database.pglite.tar.gz` (архив папки данных PGlite из работающего процесса) или `database.sql.gz` (`pg_dump`, если он установлен; в образе Docker устанавливается). Она берётся сразу после снимка, поэтому может отличаться от него на записи этих миллисекунд; сверяются json и xlsx со снимком, а копия базы — резерв на случай, когда json и xlsx не пригодны. Если `pg_dump` нет, это предупреждение в журнале, не ошибка.

Комплект собирается во временной папке `.tmp-…` и переименовывается только после проверки. Две копии в одну минуту: последняя заменяет предыдущую; страховочные комплекты перед восстановлением никогда не заменяются (к имени добавляется номер).

**3. Excel** (`tracker.xlsx`): листы «Сводка», «Проекты», «Люди», «Спринты» (цель, даты, closedAt, velocity), «Задачи» (ключ, тип, родитель-ключ, статус, приоритет, points, исполнитель-имя, спринт-название, метки, даты, описание, критерии), «Связи», «Комментарии», «История». Русские заголовки (синие), закреплённая первая строка, автофильтр, ширина колонок; служебные id и сырые значения — в последних колонках с серыми заголовками. Даты хранятся текстом ISO, чтобы Excel их не «исправлял». Ячейки длиннее предела Excel (32 767 символов) обрезаются с пометкой и предупреждением (полный текст — в json). Пароли в Excel не попадают.

**4. Библиотека.** `write-excel-file` (запись) и `read-excel-file` (чтение): обе развиваются (релизы 2026 года), зависят от `fflate` и небольших XML-парсеров, `npm audit` — 0 уязвимостей. Пакет `xlsx` с npm не используется: он заброшен, а его актуальные версии не публикуются в npm. ExcelJS отвергнут: последний релиз в декабре 2024 и устаревшие зависимости (archiver, unzipper 0.10). `write-excel-file` не умеет автофильтр, поэтому после записи в XML листов дописываются `<autoFilter>` и имена `_xlnm._FilterDatabase` через `fflate`; результат проверен чтением openpyxl и открытием в LibreOffice.

**5. Расписание.** Внутри сервера: раз в минуту проверка; копия ежедневно в `BACKUP_TIME` (18:00 по местному времени сервера) и при запуске, если удачной копии нет или ей больше 24 часов. После ошибки повтор не чаще раза в час. `BACKUP_AUTO=false` отключает автокопирование (остаются кнопка и команда). В Docker часовой пояс — переменная `TZ`.

**6. Проверка и журнал.** После создания json и xlsx читаются заново, количества и состав id по всем сущностям сверяются со снимком, json проверяется схемой Zod. Результат — строка в `BACKUP_DIR/backup-log.txt` (`дата | OK/ОШИБКА | комплект | причина | состав или текст ошибки`). Непрошедшая проверка = копия не создана (комплект удаляется) и ошибка в журнале. Результат последнего запуска держится и в памяти, поэтому ошибка видна, даже если журнал недоступен.

**7. Ротация.** Остаются последний комплект каждого из `BACKUP_KEEP_DAILY` (30) последних дней и последний комплект каждого из `BACKUP_KEEP_MONTHLY` (12) последних месяцев; остальное удаляется. Ротация трогает только папки вида `ГГГГ-ММ-ДД_ЧЧ-ММ`: чужие файлы и комплекты `before-restore_…` не удаляются. Дополнительные копии за один день (например, ручные) заменяются последней.

**8. Интерфейс (только администратор)**, блок на экране «Настройки»: дата и статус последней копии, следующая по расписанию, **выбор папки для копий** (поле пути, «Обзор…» со списком папок компьютера сервера, «Сохранить»), кнопки «Сделать копию сейчас» и «Скачать Excel» (из последнего комплекта), список последних копий. При ошибке или отсутствии копий дольше двух суток — красная полоса на всех экранах администратора. Папка проверяется (полный путь, запись, не внутри папки данных базы), хранится в таблице `settings` и сильнее `BACKUP_DIR`; после сохранения сразу делается первая копия, прежние остаются на старом месте. Просмотр папок открывает только имена каталогов (без скрытых), только администратору.

**9. Восстановление** — только из командной строки: `npm run restore <папка-комплекта> [--source json|xlsx] [--yes]`. Источник по умолчанию — json; если он повреждён, берётся Excel с пометкой. Сначала проверка (структура Zod, целостность ссылок, повторы id, совпадение заявленных и реальных количеств) и отчёт «что будет восстановлено» (сейчас в базе → из копии), затем подтверждение. Перед заменой текущая база автоматически сохраняется комплектом `before-restore_…`; без этой копии восстановление не начинается. Замена всех данных идёт в одной транзакции под блокировкой записи; сессии входа закрываются. Из Excel пароли не восстанавливаются: учётки получают временные пароли, которые показываются один раз. Из Excel пустая строка и пустая ячейка неразличимы (в истории пустые «было/стало» станут пустыми значениями), пробелы по краям текста обрезаются. Со встроенной базой команда требует остановленный трекер; настроек (`settings`) восстановление не касается.

**10. Права.** Все маршруты `/api/admin/backups…` — действие `backups.manage`, только администратор ([ADR-010](010-server-auth-roles.md)).

## Рассмотренные варианты

- **Копия средствами базы (`pg_dump`) вместо json.** Нужен установленный клиент и совпадение версий; json работает везде и проверяется схемой. Копия базы сохранена как резерв.
- **Восстановление из интерфейса.** Замена всех данных слишком разрушительна для кнопки в браузере; команда с отчётом и подтверждением безопаснее.
- **Планировщик ОС (cron, Планировщик заданий Windows).** Для новичка сложнее; встроенный планировщик работает, пока работает трекер, а при запуске догоняет пропущенное.

## Последствия

- Копия содержит хэши паролей (в `tracker.json` и копии базы): папку в облаке нужно защищать так же, как сам трекер. В `tracker.xlsx` хэшей нет, но есть почты.
- Каждый комплект на встроенной базе занимает около 5 МБ (архив PGlite); 30 + 12 комплектов — порядка 200 МБ.
- Если компьютер выключен в `BACKUP_TIME`, копия делается при запуске или в ближайшую минуту после включения.
- Копия базы PostgreSQL в Docker требует `pg_dump` в образе (добавлен); без него комплект состоит из json и xlsx.
