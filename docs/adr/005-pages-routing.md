# ADR-005. Маршруты SPA на GitHub Pages

- **Статус:** принято
- **Дата:** 2026-10-28

## Контекст

Демо публикуется на GitHub Pages по адресу `https://<владелец>.github.io/team-tracker/`. Pages раздаёт статику и не умеет перенаправлять любой путь на `index.html`. Требование качества: у каждой задачи, доски и спринта обычный адрес, который можно открыть напрямую.

## Решение

- Используется обычная маршрутизация по истории (`createBrowserRouter`) с базовым путём из настройки сборки (`base` в Vite, в CI для Pages — `/team-tracker/`).
- При сборке `dist/index.html` копируется в `dist/404.html`: на неизвестный путь Pages отдаёт `404.html`, и приложение само открывает нужный экран.
- Публикация — GitHub Actions, только из `main`.

## Рассмотренные варианты

- **Хэш-маршруты** (`/#/projects/DEMO/board`) — работают без обходных путей, но адреса некрасивые и отличаются от будущих серверных.
- **Редирект через `sessionStorage` в `404.html`** — сложнее и ломает кнопку «назад» при первом заходе.

## Последствия

- Прямые ссылки на экраны работают; Pages отвечает на них статусом 404, браузер при этом показывает приложение (для демо приемлемо).
- На рабочем сервере (этап 8) веб-сервер сам отдаёт `index.html` для неизвестных путей; изменений в коде не требуется.
